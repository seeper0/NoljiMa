# NoljiMa 사용 시나리오

## 시나리오 1: Claude Code 작업 중 사용자 확인 대기

### 상황
Claude Code가 중요한 코드 변경을 완료했고, 사용자의 확인을 받아야 다음 단계로 진행할 수 있는 상황

### 워크플로우

```bash
# === Claude Code 작업 ===

# 1. 코드 리뷰 필요 단계 완료
echo "데이터베이스 마이그레이션 코드 작성 완료"

# 2. 사용자에게 알림 전송
noljima "[작업#DB001] 데이터베이스 마이그레이션 코드 작성 완료. 검토 후 응답 부탁드립니다."
# → 텔레그램 알림 전송 성공
# → exit 0

# 3. 사용자 응답 대기 (최대 30분)
echo "사용자 응답 대기 중..."
noljima --wait "[작업#DB001]" --timeout 1800

# === 사용자 행동 (텔레그램) ===
# 핸드폰으로 텔레그램 확인
# 메시지: "[작업#DB001] 데이터베이스 마이그레이션 코드 작성 완료. 검토 후 응답 부탁드립니다."
#
# 코드 검토 후 응답 입력:
# → "[작업#DB001] 확인완료, 마이그레이션 실행해주세요"

# === NoljiMa 폴링 ===
# getUpdates API 호출 중... (30초 간격)
# → 새 메시지 발견!
# → 패턴 "[작업#DB001]" 일치 확인
# → "응답 메시지 수신: [작업#DB001] 확인완료, 마이그레이션 실행해주세요"
# → exit 0

# 4. Claude Code 작업 재개
echo "사용자 확인 완료, 마이그레이션 실행 시작"
dotnet ef database update
```

### 결과
✅ 사용자가 부재중이어도 Claude Code가 알림을 보내고 대기
✅ 사용자가 편한 시간에 확인 후 응답
✅ 응답 즉시 Claude Code 작업 재개

## 시나리오 2: 빌드 실패 시 사용자 선택 대기

### 상황
자동 빌드 스크립트 실행 중 오류 발생, 사용자에게 재시도/중단 선택을 받아야 함

### 워크플로우

```bash
#!/bin/bash
# auto-build.sh

# 1. 빌드 시작
dotnet build

# 2. 빌드 실패 확인
if [ $? -ne 0 ]; then
    # 3. 사용자에게 알림
    BUILD_ID="build-$(date +%s)"
    noljima "[${BUILD_ID}] 빌드 실패. 재시도(retry) 또는 중단(abort)을 선택해주세요"

    # 4. 응답 대기 (10분)
    noljima --wait "[${BUILD_ID}]" --timeout 600

    # 5. 응답 확인 (응답 메시지는 별도 파일에 저장 가능하도록 개선 필요)
    # 현재는 exit code만 확인
    if [ $? -eq 0 ]; then
        echo "사용자 응답 수신, 스크립트 계속 진행"
        # 재시도 로직 실행
    else
        echo "타임아웃 또는 오류, 빌드 중단"
        exit 1
    fi
fi
```

### 텔레그램 대화
```
[봇] [build-1735689600] 빌드 실패. 재시도(retry) 또는 중단(abort)을 선택해주세요

[사용자] [build-1735689600] retry
→ 스크립트 재개, 빌드 재시도
```

## 시나리오 3: 다중 알림 및 순차 대기

### 상황
여러 단계의 작업을 진행하면서 각 단계마다 사용자 확인 필요

### 워크플로우

```bash
#!/bin/bash
# deploy.sh - 배포 자동화 스크립트

DEPLOY_ID="deploy-$(date +%Y%m%d-%H%M%S)"

# === Step 1: 테스트 실행 ===
echo "Step 1: 테스트 실행 중..."
npm test

if [ $? -ne 0 ]; then
    noljima "[${DEPLOY_ID}] Step 1 실패: 테스트 실패, 배포 중단"
    exit 1
fi

noljima "[${DEPLOY_ID}] Step 1 완료: 모든 테스트 통과. Step 2 진행 승인 필요"
noljima --wait "[${DEPLOY_ID}]" --timeout 600

if [ $? -ne 0 ]; then
    echo "사용자 응답 없음, 배포 중단"
    exit 1
fi

# === Step 2: 스테이징 배포 ===
echo "Step 2: 스테이징 배포 중..."
./deploy-staging.sh

noljima "[${DEPLOY_ID}] Step 2 완료: 스테이징 배포 완료. 검증 후 프로덕션 배포 승인 필요"
noljima --wait "[${DEPLOY_ID}]" --timeout 1800  # 30분 대기

if [ $? -ne 0 ]; then
    echo "사용자 응답 없음, 프로덕션 배포 중단"
    exit 1
fi

# === Step 3: 프로덕션 배포 ===
echo "Step 3: 프로덕션 배포 중..."
./deploy-production.sh

noljima "[${DEPLOY_ID}] Step 3 완료: 프로덕션 배포 성공!"
```

## 시나리오 4: Claude Code 코드 리뷰 워크플로우

### 상황
Claude Code가 대규모 리팩토링을 완료, 사용자 승인 후 다음 작업 진행

### Claude Code 스크립트 (pseudo-code)

```python
# claude_workflow.py

import subprocess
import time

def run_noljima(message):
    """NoljiMa로 메시지 전송"""
    subprocess.run(['noljima', message], check=True)

def wait_for_response(pattern, timeout=600):
    """사용자 응답 대기"""
    result = subprocess.run(
        ['noljima', '--wait', pattern, '--timeout', str(timeout)],
        capture_output=True
    )
    return result.returncode == 0

# === 작업 시작 ===
task_id = f"refactor-{int(time.time())}"

# 1. 리팩토링 수행
print("리팩토링 시작...")
# ... 코드 분석 및 리팩토링 ...
print("리팩토링 완료")

# 2. 사용자에게 알림
run_noljima(f"[{task_id}] 인증 모듈 리팩토링 완료. 15개 파일 수정됨. 검토 후 커밋 승인 부탁드립니다.")

# 3. 사용자 응답 대기 (최대 1시간)
print("사용자 응답 대기 중... (최대 60분)")
if wait_for_response(f"[{task_id}]", timeout=3600):
    print("✅ 사용자 승인 받음, 커밋 진행")

    # 4. Git 커밋
    subprocess.run(['git', 'add', '.'], check=True)
    subprocess.run(['git', 'commit', '-m', 'refactor: 인증 모듈 리팩토링'], check=True)

    # 5. 완료 알림
    run_noljima(f"[{task_id}] 커밋 완료: refactor: 인증 모듈 리팩토링")
else:
    print("❌ 타임아웃 또는 거부, 커밋 중단")
    run_noljima(f"[{task_id}] 타임아웃으로 커밋 중단됨")
```

### 텔레그램 대화

```
[봇] [refactor-1735689600] 인증 모듈 리팩토링 완료. 15개 파일 수정됨. 검토 후 커밋 승인 부탁드립니다.

# 사용자가 IDE에서 코드 검토 (10분 소요)

[사용자] [refactor-1735689600] 검토 완료, 커밋 승인

[봇] [refactor-1735689600] 커밋 완료: refactor: 인증 모듈 리팩토링
```

## 시나리오 5: 타임아웃 처리 (응답 없는 경우)

### 상황
사용자가 응답하지 않아 타임아웃 발생

### 워크플로우

```bash
#!/bin/bash

TASK_ID="urgent-$(date +%s)"

# 1. 긴급 알림 전송
noljima "[${TASK_ID}] 긴급: 서버 디스크 사용률 95%. 로그 삭제 승인 필요"

# 2. 5분만 대기
noljima --wait "[${TASK_ID}]" --timeout 300

# 3. Exit code 확인
if [ $? -eq 0 ]; then
    echo "✅ 사용자 승인, 로그 삭제 진행"
    find /var/log -name "*.log" -mtime +30 -delete
    noljima "[${TASK_ID}] 로그 삭제 완료"
else
    echo "❌ 타임아웃 - 사용자 응답 없음"
    noljima "[${TASK_ID}] 타임아웃: 사용자 응답 없어 작업 중단"

    # 관리자에게 에스컬레이션
    noljima "[ADMIN] ${TASK_ID} 타임아웃, 수동 확인 필요"
    exit 1
fi
```

```
# 5분 경과... 사용자 응답 없음
```

## 시나리오 6: 여러 ID 동시 관리

### 상황
여러 작업이 동시에 진행되며, 각각 다른 ID로 관리

### 워크플로우

```bash
# Terminal 1: 프론트엔드 빌드
#!/bin/bash
FRONTEND_ID="fe-build-001"
npm run build
noljima "[${FRONTEND_ID}] 프론트엔드 빌드 완료, 배포 승인 필요"
noljima --wait "[${FRONTEND_ID}]" --timeout 600

# Terminal 2: 백엔드 테스트
#!/bin/bash
BACKEND_ID="be-test-001"
dotnet test
noljima "[${BACKEND_ID}] 백엔드 테스트 완료, 결과 확인 필요"
noljima --wait "[${BACKEND_ID}]" --timeout 600

# Terminal 3: 데이터베이스 백업
#!/bin/bash
DB_ID="db-backup-001"
./backup-database.sh
noljima "[${DB_ID}] 데이터베이스 백업 완료, 검증 필요"
noljima --wait "[${DB_ID}]" --timeout 600
```

### 텔레그램 대화

```

15:01 [봇] [be-test-001] 백엔드 테스트 완료, 결과 확인 필요
15:02 [봇] [db-backup-001] 데이터베이스 백업 완료, 검증 필요
```

## 구현 시 고려사항

### 1. 응답 메시지 내용 추출 (향후 개선)
현재 명세에서는 exit code만 확인 가능. 향후 다음 기능 추가 고려:

```bash
# 응답 메시지를 파일로 저장
noljima --wait "[작업#001]" --output response.txt

# response.txt 내용
# [작업#001][retry]

# 스크립트에서 파싱
RESPONSE=$(cat response.txt | grep -oP '\[작업#001\]\[\K[^\]]+')
if [ "$RESPONSE" == "retry" ]; then
    echo "재시도 진행"
elif [ "$RESPONSE" == "abort" ]; then
    echo "작업 중단"
fi
```

### 2. 멀티 패턴 대기 (향후 개선)
```bash
# 여러 ID 중 하나라도 응답 오면 종료
noljima --wait-any "[작업#001]" "[작업#002]" --timeout 600
```

### 3. 응답 형식 검증 (향후 개선)
```bash
# 정규식 패턴으로 응답 검증
noljima --wait "[작업#001]" --pattern "^(retry|abort)$"
```
